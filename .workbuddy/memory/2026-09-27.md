- 引擎 `EngineService`（纯确定性数值计算，不碰 LLM），常量：η=0.25、收敛阈值 0.75、
  C_MAX=0.95、ε=0.01、追问信号阈值 1.5、MAX_QUESTIONS=30。
- 状态单位 = 考察点 `AssessmentPointState(θ, c, answerCount)`，θ 初值 0、c 初值 0。
- 期望正确率 r̂ = 1/(1+e^(−2.5(θ−d)))，d = 难度档/5；u = 1−|2r̂−1|+0.1；s = (r−r̂)/u。
- 更新：m = 1−|θ−d|；θ' = clamp(θ+0.25·s·m,0,1)；consistency = max(0.2,1−|s|/3)；
  c' = min(0.95, c+0.5(1−c)·consistency)。答题权重：单选/判断 0.5，其余 1.0。
- 三级选题：① 选点 f = w(1−c)+ε ② 选难度档（本点最近2题 r 均值≥0.8 升档、<0.5 降档；
  不够则用本维度均值；再不够用画像就近档，默认 L3）③ 按 考察点+难度+未做过 选题，
  目标档优先再向两侧 ±1…±4 扩散。某点所有难度无题 → 该点置 removed 换下一个 active。
- 追问触发：needFollowUp = (r < r̂ 且 |s| ≥ 1.5) 或 clarity == low。
  追问时暂不更新 θ/c，等 followupResult 用 rFinal 重算再更新。
- 追问终止：turns ≥ 3、学生说不知道/不会/no idea、或模型返回 JSON（纯文本=继续追问）。
- 收尾：reportData「乙方案」未测完不出分（还有 active 且题数<30 → 返回 incomplete）；
  总分 = 100·Σ(θ·w)/Σw（只算 answerCount>0 的点）；维度分 = 维度内已测点 θ 均值×100；
  60 分划强弱项。画像：30 天半衰指数衰减，profile = Σ(c·θ)/Σc。

### Python 版（历史，agent-python）
- LangGraph 单节点 `agent_turn`：决策轮（`call_tool`，tool_choice=required，temperature=0，
  二选一 ask_followup / next_question）+ 发言轮（按 action 选 DIALOGUE_SYSTEM / CLOSING_SYSTEM）。
- 判定ting man：确定性规则优先（学生说跳过类词 ≤40字 / 轮次达 max_topic_turns）→ 强制 next_question。
- 评分只在 `next_question` 后调一次；失败不写 0 分，记 scoring_failed。
- 出题 `RandomEngine`：范围内随机抽未用过的题（非自适应）。
- 聚合：题分平均→考察点→维度→综合；等级 L0–L5（60/70/80/90 档）；建议规则式不调 LLM。

### 两版关键差异
触发评分时机（Python：关题才评；Java：每答必评，追问结束再评一次）、
追问判据（Python：模型工具调用；Java：数值信号 + clarity）、
出题（随机 vs θ/c 三级自适应）、口径（题分平均 vs θ 加权）。

## 第四轮：用户二次调参（ETA 1.0→0.75、C_GROWTH 0.75→0.5）+ 新增对话题/实操题

## 第六轮：核实「权重算分是否真的实现」

结论：**主链路是真的实现了**，四处齐备：
教师建班表单 `TeacherClassesPage:327` 传 `pointWeights`（0-10 整数）
→ `classes.point_weights`（列已在 database.sql 与 01_engine.sql）
→ `EngineService.loadClassWeights(classId)`（第209行）
→ `resolvePoints` 生成 PointWeight → 快照写 `assessments.point_weights`（第107/140行）
→ `reportData` 第778-793 行：`w = weightMap.getOrDefault(point,1.0)`、
  `thetaSum += θ·w`、`wSum += w`、`totalScore = 100·Σ(θ·w)/Σw`。

会让权重「实际不生效」的四个场景：
1. **只对教师任务生效**：`resolvePoints` 仅 `taskId != null` 分支调 loadClassWeights；
   自主练习分支权重恒 1.0（第197行）。
2. **权重 0 被当成 1**：`loadClassWeights` 第221行 `if (w > 0)` 过滤掉 0，
   落到 `getOrDefault(...,1.0)`。而教师端滑块默认值就是 0（TeacherClassesPage:380）
   → 教师没逐个调过的点全是 0 → 全部回退 1.0 → 实际等权。**这是最常见的"权重没效果"原因。**
3. **只在首次初始化考察点时快照**：第100/134行"pointStates 已存在"分支直接 return，
   不写 point_weights。先测评后设权重，或教师中途改权重，对已开始的测评都不生效。
4. 只有一个考察点时 Σ(θ·w)/Σw 恒等于 θ，加权无意义。

权重**没接进**的地方：出题优先级（pickPoint 第431行 w 仍硬编码 1.0）；
θ 更新不看权重（这条合理，不建议改）。
另：`assessment_tasks.point_weights` 是死列（代码改读班级表），教师端也无任务级权重入口。

用户确认的设计意图（第七轮）：**教师发布的任务要加权、是预期设计**；
自主练习等权——是否也要跟随班级权重，待用户决定（改动只是一行：
把 `loadClassWeights` 的调用提到 `resolvePoints` 两个分支共用）。

**重要辨析**：总分 32.32 与六维简单平均（约48）的差异有**两个可能来源**，不能只归因于权重：
① 班级权重；② **聚合层次不同**——总分是「每个考察点一票」，六维平均是「每个维度一票」，
若低分维度的考察点数量多，总分就会被拉低。区分二者必须查 `assessments.point_weights` 快照。层级。
